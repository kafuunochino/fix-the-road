# 未完成局金币预留与恢复

版本：0.3.1。金币是本地游戏奖励，不涉及真实货币、充值或第三方交易。

## 选择的方案

不恢复整盘道路局面，而是对未通关局自动退款。当前局12金币加班券、20金币复活均先从可用余额中预留，同时把同一条存档里的 pendingPurchase 凭证写入。凭证只包含随机局标识、关卡号和两种已购标记，金额由固定价格推导，不接受任意退款数值。完整扣款与凭证写入并回读匹配后，才给本局效果。

- 成功验收：清除凭证、保留扣款，同次保存首通标记和首次20金币奖励。
- 免费重开、选别关、永久离开、刷新：退回当前未通关局全部预留金额，清除凭证，并放弃本局效果和局面。
- 失败面板、打开/关闭工具或地图、临时后台、bfcache恢复：仍是同一局，保留预留金额及效果；不会退款后继续用原效果。
- 无论是否支付/看模拟广告，均有免费重开。每局一张加班券，一次复活（金币与广告共用一次上限）。

## 异常与幂等

- 重复点击、重复退款、重复刷新不得再扣款或多返金币。
- 写入前失败：不扣余额、不发效果；玩家仍可免费重开。
- 写入后抛错：只有精确回读完整存档成功才认提交。不能回读确认则不发效果，并提示重新打开核对，已有凭证将在下次可读启动时退款。
- 退款写入失败：旧扣款与旧凭证仍在存储，下一次启动从这对旧数据算出同一余额，绝不按内存退款结果再次累加。
- 通关存档写入失败：未保存的首通奖励/通关记录不能作为持久奖励。重新打开会从最后成功写入的凭证退款，重开当前段；不会既保留未提交奖励又重复领首通。
- 消费凭证包含在v2本地存档内；旧v1和无凭证的v2记录仍能迁移读取。未包含凭证的历史0.3.0消费无法凭空还原，因此修复包应替代旧候选。
- 旧页面发现当前存储不再是自己的最后成功版本，会拒绝覆盖并标为存储冲突。此检查不是跨进程原子CAS，没有服务端经济；建议仅保留一个活跃页面。

## 诊断与测试

只读诊断增加 pendingPurchase、pendingPurchaseCoins、storageConflict、storageUncertain。测试仅模拟宿主与存储，调用实际交付HTML中未经替换的脚本和浏览器适配器，不直接设置游戏状态。真实浏览器、手机和抖音工具仍未验收。
